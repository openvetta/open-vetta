## 1. 一句话：为什么这样分层

**【二开要改】** 划分轴是「**会不会被别的包 import**」，不是「用了什么语言 / 框架」。

- `apps/`：可交付应用，依赖图的**叶子**，不被任何包 import。现在主清单是 desktop、cli-host、docs-site、mobile、im-gateway。  
- `packages/`：可复用模块，只能被 `apps/` 或其他 `packages/` 依赖。

箭头**只能向下**：叶子应用可以换、可以多个（Desktop / CLI / IM），下面的产品策略和内核不能认识窗口、Electron、某个 app 路径。反向 import 有机械守卫。

### 四层 I/O（新手最容易改错）

| 层 | 有没有 Node / Electron I/O | 典型包 |
|---|---|---|
| 协议 | **无**。可移植边界，可被非 Node 宿主实现 | `runtime-core` / `runtime-tools` / `runtime-mcp` / `runtime-storage` |
| Node 实现 | 有 fs / 进程 / stdio。Desktop 和 CLI **共用**这一套 | `runtime-node` |
| Desktop 装配 | 有进程级组合；**不得** import `apps/desktop` | `runtime-desktop` |
| 窗口 / 页面 | Electron UI 叶子，不被 packages import | `apps/desktop` |

产品或平台的 **Composition Root** 负责选择和配置适配器；协议包不包含 Node I/O。`runtime-mcp/src` 不得导入平台 Runtime 或 `node:*`。

### 一句话所有权

**Session 是 runtime-core 的；循环是 agent-core 的；产品话术是 coding-agent 的；文件 / 进程是 runtime-node 的；窗口是 desktop 的。**

`coding-agent` **不是** Kernel，也 **不是** Composition Root：

| 它拥有 | 它不拥有 |
|---|---|
| Prompt / Skill / MCP 投影 / Mode / 权限文案 | Session 生命周期、本轮准入、read/bash 实现、Electron |
| 产品 Feature 的工具名、何时暴露、结果怎么投影 | 选择 `@vetta/runtime-node` 的默认实现（只允许现有平台 Composition Root 选） |

`agent-core` 是「单次 Agent 执行的最小内核」：工具循环、错误、取消、usage、stop。不拥有 Session 生命周期、本轮准入、队列、运行时快照、产品 Feature、持久化或平台 I/O。

换宿主（Desktop → CLI → IM）不该改内核。这就是分层的全部理由。

## 2. 两张图

### a) 仓级箭头

根 `AGENTS.md` 原文：

```text
apps/*  (desktop / cli-host / docs-site / mobile / im-gateway)
                      |
                      v
       coding-agent / runtime-* / capability-*
                      |
                      v
                 agent / ai
```

贴近桌面装配时再记一张（`runtime-desktop` README）：

```text
desktop → runtime-desktop → coding-agent + runtime-node
                              └→ runtime-core + 各 runtime 协议
```

`runtime-desktop` **不得**反向依赖 `desktop`。`packages/*` 不得反向依赖 `apps/*`。跨包只走 `package.json#exports`，禁止 `@vetta/foo/src/**`。

### b) 用户点发送怎么穿过

上一篇讲「想 → 工具 → 再想」。这里只跟**文件**，第一周跟到 `runtime.prompt` 即可，不必再讲循环故事。

```text
Renderer 输入栏
  apps/desktop/src/renderer/domains/conversation/hooks/useSessionMessageSender.ts
    → window.vetta.session.prompt          # preload 合同
      apps/desktop/src/preload/api-types/session.ts
Main IPC（薄，只转发，不写策略）
  apps/desktop/src/main/ipc/session.ts
    → DesktopConversationService
      apps/desktop/src/main/conversations/desktop-conversation-service.ts
        → this.runtime.prompt(...)         # RuntimeHost，runtime-core
              │
              ├→ 本轮快照锁定 Tool / Skill / MCP
              ├→ coding-agent 编 Prompt、投影工具表
              └→ agent-core 驱动循环
                    ├→ @vetta/ai 调模型
                    └→ runtime-node 执行工具（fs / 进程 / MCP client）
UI 订阅事件：流式文字、工具卡片、权限抽屉
```

**【不要做】** 第一周不要从 `packages/agent/src/agent-loop.ts` 往下挖。循环仍在 agent-core，本篇关心的是**为什么发送路径不能在 IPC 里写策略**。

### Composition Root（谁负责接线）

| 宿主 | Composition Root | 注意 |
|---|---|---|
| Desktop | `packages/runtime-desktop`（`createDesktopCodingAgentToolEnvironment`）+ `apps/desktop` 装配 | 窗口代码不得被 packages import |
| CLI / RPC sidecar | `apps/cli-host`（终端宿主，**不是** Agent 本身） | 不要在 cli-host 里找对话渲染或工具执行 |
| 公开 SDK 零配置 | coding-agent `host/` 兼容根 | **新能力不要往这里加** |

`coding-agent` **不**选 `runtime-node` 默认实现。协议包和 `runtime-node` **不得**反向依赖 coding-agent。

## 3. Desktop 四层

栈：**Electron 34 + Vite + React 19 + Jotai + TanStack Router**（hash history，适配 `file://`）。

```text
src/main/        主进程：原生、生命周期、领域业务服务
  ipc/           薄注册层 —— 禁止承载业务
src/preload/     安全桥；对外合同定义在这里
src/renderer/    React UI，按 domains/ 分
```

### 动手前先读

| 你改什么 | 先读 |
|---|---|
| 任何 Desktop | [`apps/desktop/AGENTS.md`](../apps/desktop/AGENTS.md) |
| renderer `.tsx` / `.css` | 同目录 [`DESIGN.md`](../apps/desktop/DESIGN.md) |
| IPC | [`ipc/AGENTS.md`](../apps/desktop/src/main/ipc/AGENTS.md) |
| App Action | [`app-actions/AGENTS.md`](../apps/desktop/src/main/app-actions/AGENTS.md)（实现已在插件 `vetta-actions`） |
| 监控 | [`app-monitor/AGENTS.md`](../apps/desktop/src/main/app-monitor/AGENTS.md)（旁路，不得阻塞业务） |

### IPC 硬规则

允许：注册 `ipcMain.handle`、最小校验、调用 main 业务服务、返回。  
禁止：策略、状态机、持久化、窗口编排。  
业务服务不得反向 import `main/ipc/*`。对外行为以 preload / shared 类型为准。

口诀：**IPC 是入口，业务模块才是能力所有者。**

用户可见文案走 i18n（`apps/desktop/src/shared/i18n/locales/zh/`，如 `chat.json`），**禁止**硬编码。快捷键进现有 keybinding，不在业务逻辑里写死。

## 4. 第一周改哪里（主体）

CONTRIBUTING 原意：最有杠杆的贡献通常是**一个目录**，不是框架重写。扩展轻重：**Skill < MCP < Plugin**。简单流程不必做成插件。

### A. Desktop UI

| | |
|---|---|
| **改哪** | [`apps/desktop/src/renderer/domains/`](../apps/desktop/src/renderer/domains)（conversation / settings / project…）；共享 [`renderer/shared/`](../apps/desktop/src/renderer/shared) |
| **文案** | [`apps/desktop/src/shared/i18n/locales/zh/`](../apps/desktop/src/shared/i18n/locales/zh) |
| **先读** | `apps/desktop/AGENTS.md` + `DESIGN.md`（任何 `.tsx` / `.css`） |
| **最小验证** | 见下方命令块 |
| **不要** | 在 [`ipc/`](../apps/desktop/src/main/ipc) 写策略；默认跑 `verify:ui:*`（UI 改动本身不构成授权） |

```bash
bun run check:quick -- <改过的文件>
bun run test:impact -- <同样文件>
bun run check                          # 一轮结束；不含测试
```

### B. 加 Skill

| | |
|---|---|
| **改哪** | 内置：[`packages/skill-presets/<name>/`](../packages/skill-presets)（一个带 `SKILL.md` 的目录）+ 改 [`skills-manifest.json`](../packages/skill-presets/skills-manifest.json)；参考现有 [`create-skill`](../packages/skill-presets/create-skill/SKILL.md) |
| **先读** | CONTRIBUTING 那一行；落点规则在 create-skill 的 SKILL.md「Choose the target」 |
| **最小验证** | `bun run --cwd packages/skill-presets test`（包脚本走 `run-vitest.mjs`） |
| **不要** | 简单流程做成插件；产品策略不要改到 `apps/desktop` |

### C. 加 MCP

| | |
|---|---|
| **用户侧（第一次贡献优先）** | 侧栏 **能力** → 手动添加 MCP。配置 `~/.vetta/agent/mcp.json`。文档：[`product/mcp.mdx`](../apps/docs-site/content/docs/product/mcp.mdx)（设置页不再单独挂 MCP 页签） |
| **改协议（不要当第一次）** | 协议 [`packages/runtime-mcp`](../packages/runtime-mcp)；stdio / HTTP 在 `runtime-node/mcp` |
| **不要** | 在协议包里写凭证文件 / 子进程；把 MCP 做成桌面插件 |

### D. 加 Plugin

| | |
|---|---|
| 仓内系统插件 | [`packages/plugins/presets/`](../packages/plugins/presets)（参考 [`svg-viewer/plugin.json`](../packages/plugins/presets/svg-viewer/plugin.json)） |
| 仓内示例外置 | [`packages/plugins/externals/`](../packages/plugins/externals) |
| **仓外（手册推荐给 Agent）** | `npx @vetta-org/plugin-cli init`；手册随 SDK 进 `node_modules`，用 `npx vetta-plugin-cli docs` |
| **先读** | [`packages/plugins/AGENTS.md`](../packages/plugins/AGENTS.md) + 手册真源 [`docs/plugin/getting-started.md`](plugin/getting-started.md) |
| **最小验证** | 按手册构建 zip、装进 Desktop；改对外合同必须同步 `docs/plugin/` |
| **不要** | deep-import `apps/desktop/src/**`；Preset 写进 `~/.vetta/plugins` |

Preset 随 App 发布，权限自动授予，不可卸载，**不进** `~/.vetta/plugins`。外置 zip 用户安装授权，可卸载。

### E. 改 CLI

| | |
|---|---|
| **改哪** | [`apps/cli-host`](../apps/cli-host)：命令分发、进程、`vetta` / `vetta-agent` / `vetta-agent-rpc` |
| **先读** | [`apps/cli-host/AGENTS.md`](../apps/cli-host/AGENTS.md) |
| TUI / Loop **不在这里** | TUI：`packages/coding-agent/src/modes/interactive/`；Loop：`packages/agent` |
| **最小验证** | 参数 / 输出变了：`bun run verify:runtime-contract`；bin / exports 变了：`bun run verify:artifact:installed` |
| **不要** | 反向依赖 `@vetta/desktop`；在 cli-host 里找对话渲染或工具执行 |

### 不要当第一次贡献

- 改 **agent-core Loop**（[`packages/agent/AGENTS.md`](../packages/agent/AGENTS.md)：`agent-loop.ts` 最关键）
- 换包管理器 / 渲染框架 / 重写 Agent Loop（CONTRIBUTING 明确不接受）
- **加 workspace 包**（除非真要新包）：必须同时改 workspaces + tsconfig path maps，见 [`docs/monorepo-new-package.md`](monorepo-new-package.md)

## 7. 守卫与容易说错

两道机械守卫，删检查 / 放宽基线掩盖违规不被允许。

| 脚本 | 拦什么（一句） |
|---|---|
| [`check-package-boundaries.mjs`](../scripts/quality/check-package-boundaries.mjs) | libs 不得 import apps；plugins 不得 deep-import `desktop/src/**`；packages 不得 import 别包 `test/`；`runtime-core` 不得 import coding-agent；`agent-core` 不得 import runtime / 产品包；协议包不得 import `runtime-node` |
| [`check-coding-agent-architecture.mjs`](../scripts/quality/check-coding-agent-architecture.mjs) | 产品域不依赖 Composition 实现；合同不反向依赖 Adapter / Host；外部只走 `package.json#exports`；旧 `src/core` / `compat` 不得恢复 |

**ADR 不是当前合同。** 当前行为以源码、公共类型、Schema、测试、机械检查为准。改行为先改实现再记 ADR，不得只改 ADR 宣称已变。事实源优先级：源码 + 最近一级 AGENTS + 守卫 > 包 README > ADR。

计费 / 配额 / 订阅 ADR **编号空洞是刻意的**（迁到私有仓 `vetta-serv`）：0016、0017、0019、0038、0039、0051、0052、0056。编号重复不修正（0021、0057、0060、0066、0068、0069）——引用时连标题。见 [`docs/adr/README.md`](adr/README.md)。
