## 0. 这篇怎么用

先钉死两件事，再往下读：

1. **一次普通会话里只有一个 Agent。** 它自己规划、自己调工具、自己检查。
2. **智能体团队 ≠ 子代理。** 团队是常驻名册、有负责人；子代理是某次任务里的临时帮手，用完即弃，不算产品意义上的多智能体协作。

| 你现在要做什么 | 读哪几节 |
|---|---|
| **只想对外讲**（这东西怎么干活、团队怎么分工） | 第 1、2、4、5 节 |
| **想搞懂内部怎么跑一轮** | 第 3、6 节 |
| **想改代码** | 第 7 节；动手前扫第 8 节 |
| **对完项目再学 Agent** | 先读 [新手入门与二开讲解.md](新手入门与二开讲解.md) |

建议顺序：**先能说清「一个 Agent 怎么交差」，再讲团队；不要把子代理讲成团队。**

## 1. 一句话

**【对外可讲】**

**普通会话里只有一个 Agent：自己规划、自己动手、自己检查。**

用户发一条消息，**不等于**模型被叫一次。更准确的说法是一轮执行：

```text
想清楚下一步 → 可能调用工具（读文件、改文件、跑命令…）→ 再根据结果想
        ↑_______________________________________________________|
```

直到交差、被你取消，或失败到需要你介入。中间可能有多次「再想」，所以最后一段回复不是验收的全部证据。

**【不要讲成卖点】** 不要对外说「一次 Turn」「Agent Loop」。对外说「一轮执行」即可。

---

## 2. 用户眼里一轮任务怎么走

**【对外可讲】** 用户不需要知道内部包名。记住五个对象、四步闭环。

### 五个对象

| 对象 | 是什么 |
|---|---|
| **工作区** | 一组本地资料，加上允许操作的边界 |
| **任务** | 目标、上下文、约束、怎么算做完 |
| **会话** | 一次连续工作的消息、工具和状态记录 |
| **执行** | 推理、工具调用、权限确认、后台工作 |
| **结果** | 回复、文件、产物、测试，以及还没解决的风险 |

### 四步闭环

```text
选工作区 / 项目
    → 写任务（可 @ 文件、/ 技能或场景）
    → 观察执行（推理、工具、权限确认）
    → 验收真实文件和执行记录，不只看最后一段回复
```

1. **选边界。** 打开已有项目、本地目录，或在默认「对话」工作区开始。要改文件时，优先用对应项目目录。
2. **给出可执行任务。** 写清目标、允许动的路径、约束和验收方式。`@` 引用文件，`/` 选技能或场景。
3. **观察和授权。** 看待办、工具卡片、后台任务。弹出权限时，核对动作和影响范围再决定。
4. **验收结果。** 核对文件变化、产物、失败的工具、仍需人工收尾的事项。模型说「已经改好了」不等于文件真的改了。

### 权限（用户能看见的那套）

| | |
|---|---|
| 两种执行模式 | **沙盒受限**（默认）/ **完全访问** |
| 单次确认 | **允许本次** / **本会话不再询问** / **拒绝** |
| 出现位置 | 权限抽屉：核对动作和范围后再点 |

**【不要讲成卖点】** `ask_user_question`（让 Agent 向你提选择题）**默认关闭**，和权限抽屉不是同一套界面。对外主路径不要把它说成默认权限模型。

### 执行过程中能看见什么

| 你看见的 | 用来干什么 |
|---|---|
| 流式文字 | 阶段性说明，不是最终验收 |
| 工具卡片 | 它实际调了什么、成功还是失败 |
| 待办 | 这一轮自己列的步骤（产品功能，不是循环内核） |
| 权限抽屉 | 敏感动作要你点头 |
| 工作区里的文件 | **真正的产物** |
| 后台任务 / 子代理卡片 | 当前 Agent 临时外包出去的活；**不进团队名册** |
| 失败后的继续 / 重试 / 分叉 | 从失败里恢复，不必从头再来 |

**【对外可讲】** 最后一段回复不是唯一证据。以工作区里的实际文件和执行记录为准。

## 3. 内部实际步骤（附录，给二开）

**【二开要改】** 这一节给改代码的人看。对外讲解跳过，或只保留「想 → 工具 → 再想」。

### 一轮怎么串起来

```text
界面发出提示
    → 主进程交给运行时：开始这一轮
    → 本轮快照锁定：用哪些工具、哪些技能（中途改技能不影响本轮）
    → 产品层编写系统提示、投影可用工具
    → 内核循环：调模型 → 若有工具则执行 → 把结果送回模型 → 直到没有工具 / 取消 / 出错
    → 界面订阅事件：流式文字、工具卡片、权限、待办
```

对应到仓库（对外不要把这些词当卖点）：

```text
Renderer  session.prompt
    → Main  RuntimeHost.prompt
    → 本轮 Snapshot 锁定 Tool / Skill
    → coding-agent 编系统提示、投影工具
    → agent-core 循环调模型、执行工具
    → UI 订阅事件
```

对话项目的工作目录在会话侧（开发数据根是 `~/.vetta-dev`）。**【不要讲成卖点】** 不要对外讲 Session 文件格式、jsonl、RuntimeHost。

### 各层干什么

| 层 | 干什么 | 不干什么 |
|---|---|---|
| Desktop（窗口 / 页面） | 发提示、画界面、权限交互、取消 | 不拥有循环内核，不编系统提示 |
| `packages/coding-agent` | 产品策略：Prompt、Skill、MCP、模式、权限文案 | 不直接调模型协议，不写 Node 文件 I/O |
| runtime-core | 会话 / 这一轮的生命周期、快照 | 不跑 Tool Loop 本身 |
| `packages/agent`（`@vetta/agent-core`） | **驱动循环**：模型调用与工具循环、流式事件、错误 / 取消 / usage / stop | 不拥有会话生命周期、本轮准入、队列、运行时快照、产品功能、持久化、平台 I/O |
| `@vetta/ai` | **调用模型** | 不执行本机工具 |
| runtime-node | **执行工具**（读文件、跑命令等） | 不编产品 Prompt |

谁驱动循环：**agent-core**。谁调模型：**`@vetta/ai`**。谁执行工具：**runtime-node**。谁编 Prompt：**coding-agent**。

### 模型实际看见什么

任务正文、你 `@` 的文件、图片、项目里的 `AGENTS.md`、技能 / 场景、知识库、插件和 MCP 提供的能力。

**【对外可讲，细节给二开】** 技能发现阶段，系统提示里只有**名称 + 描述**；全文按需加载（读取技能文件，或 `/skill:名称`）。内核自己不撰写产品提示词。

### 发送中再打字

界面始终按「后续消息」处理：空闲则新开一轮；忙碌则**排队，不丢消息**。

**【不要讲成卖点】** Agent Loop、Turn admission、jsonl、RuntimeHost、本轮准入——这些是内部词，对外只说「一轮执行」。

## 4. 子代理 vs 团队（必须先分清）

**【对外可讲】** Vetta 里有两种「多 Agent」，边界清楚。**不要把子代理讲成多智能体协作。**

| | 智能体团队 | 子代理（Subagent） |
|---|---|---|
| 产品身份 | 常驻名册：负责人 + 成员 | 当前 Agent 一次任务里的临时帮手 |
| 生命周期 | 跨回合、跨会话，有自己的历史 | 用完即弃 |
| 用户看见 | 侧栏「智能体」；可点开成员的独立会话 | 活动面板 / 派发卡片；**不进团队名册** |
| 任务归属 | 成员可持有团队任务、公开发言 | 不能持有团队任务，不能作为成员发言 |
| 工具 | 委派、等待、公开消息等协作工具 | 发起者自己私有调度 |
| 代码落点 | `@vetta/agent-team` + Desktop `agent-teams/` | `runtime-subagents`（只排队 / 并发 / 等待，不创建 Coding Agent 会话） |

硬约束：**团队成员运行时会摘掉子代理工具**，避免把团队任务偷偷外包出去、把归属弄丢。

一句话对照：

- 子代理 = 「我这轮忙不过来，请个临时工，干完就走」
- 团队 = 「公司编制：有负责人、有岗位、下次还是这几个人」

## 5. 智能体团队怎么协作

**【对外可讲】** 团队把「先设计、再实现、最后有人挑刺」拆给多个独立 Agent。每位成员有自己的职责、能力开关和私有会话；其中一位是**负责人**，是你唯一的对话入口。

### 什么时候值得开团队

| 值得组团队 | 用普通会话更划算 |
|---|---|
| 工作天然分阶段：设计 → 实现 → 审查 | 目标单一，一两轮就能做完 |
| 需要独立视角挑错，而不是作者自评 | 你要边看边改、频繁介入细节 |
| 同一批材料要多个角度，再合成一份交付 | 没有可并行或需要交接的部分 |

选**单个智能体** = 普通会话换了人设，**不是**团队协作。

### 入口和预置

入口：侧栏 **智能体**。上半是团队，下半是所有智能体。同一个智能体可以同时在多支团队任职。

首次安装由内置扩展「**预设智能体**」铺下 5 个人设和 2 支团队（不是宿主代码写死的）：

| 智能体 | 角色 |
|---|---|
| 主控 Master | 拆解、分派、验收、交付 |
| 开发员 Developer | 生产核心资产（代码、成稿、完整分析） |
| 检索员 Researcher | 搜集并核实事实 |
| 审计员 Auditor | 红队挑错 |
| 业务员 Business | 需求、范围、商业假设 |

| 预置团队 | 阵容 | 流程写在哪 |
|---|---|---|
| 开发团队 | 主控 · 开发员 · 检索员 · 审计员 | 队长的**团队任务书**（改文字即改流程） |
| 策划团队 | 主控 · 检索员 · 审计员 · 业务员 | 同上 |

物化之后就是普通文件：可改名、改职责、增删成员、整支删除；删了**不会**被重新注入。停用「预设智能体」扩展，预置会收起；你自己建的不受影响。

### 发起一次协作

```text
新建会话选团队（或智能体页「发起该团队会话」）
  → 选工作空间（不指定项目 = 本会话独占新目录；指定项目 = 项目目录）
  → 写目标发送（默认交给负责人；@ 可点名成员）
  → 主时间线只看公开进展
  → 点成员条进入该成员的私有会话
```

工作空间在会话创建时固化，协调方和全部成员**共用同一个目录**。文件是真正的共享工作台。

### 协作图

```text
你 ──只对负责人说话──▶ 公开协调时间线
                              │
                              │ 委派任务（立刻返回，不等做完）
                              ▼
              ┌───────────┬───────────┬───────────┐
              │ 检索员     │ 开发员     │ 审计员     │
              │ 私有会话   │ 私有会话   │ 私有会话   │
              │ 自己的一轮 │ 自己的一轮 │ 自己的一轮 │
              └─────┬─────┴─────┬─────┴─────┬─────┘
                    │ 发布结论   │           │
                    └───────────▶ 公开时间线
                                 负责人验收 → 再派或交付
```

每位成员仍跑第 1 节那套「想 → 工具 → 再想」。团队层不替代这一轮，只多了名册、持久任务、公开 / 私有对话。

### 三条硬规则（用户能懂）

1. **派发是异步的，所以能并行。** 任务被受理就返回 ID。不同成员真正并行；同一成员的多项任务排队。等待超时 ≠ 失败，也不会取消任务。完成通知会唤醒发起方。系统拒绝环形等待。
2. **归属不偷转。** 默认「负责人分派」：只有负责人能委派和取消。成员信息不足就问或回报，不把任务转手给别人。
3. **完成必须有公开结果。** 没有已发布的结果消息，就不能标「已完成」。失败按原因分类：网络 / 限流可自动重试；鉴权 / 余额等外部条件修好再唤醒；上下文超长要人介入；非法请求不重试。

流程不是代码写死的，写在队长的**团队任务书**里。

### 用户看见什么

| 界面 | 含义 |
|---|---|
| 顶部成员条 | 本次名册；负责人有标记。点成员进入**它的独立会话**看完整过程 |
| 成员状态 | 等待 / 思考 / 调工具 / 完成 / 失败 |
| 委派步骤 | 负责人把有边界的目标交给某人，任务此刻才开始排队 |
| 主时间线 | 只显示公开进展：计划、委派、各成员结论 |
| 活动面板 | 团队会话只开放**文件**和**浏览器**页签 |

团队会话按会话隔离草稿、附件、输入历史与模型配置。同一支团队可以同时开多个互不干扰的会话。它们出现在侧栏对话列表，但**不会混进普通对话搜索**。

### 成熟度（必须降调）

| 事实 | 对外怎么说 |
|---|---|
| 公开文档覆盖状态是 complete | 这是正式产品能力，不是 developer-preview |
| 本机文件 + 本机运行时 | **没有**跨设备同步，**没有**服务端多人协作 |
| 实时流式汇总、更复杂的负责人编排仍待后续 | 不要讲成分布式集群或云端多智能体平台 |
| 预置来自插件 | 停用扩展则预置收起；用户自建不受影响 |

**【对外可讲】** 「一支有负责人的常驻团队，本机并行分工，共享文件和结论。」  
**【不要讲成卖点】** 不要讲成云端平台、跨账号协作或计费——那些不在本仓。

## 6. 通信（用户能懂，不抄协议）

**【对外可讲】** 一个团队会话 = **N+1 条对话**：1 条公开协调 + 每位成员 1 条私有。

### 谁看得见什么

| 内容 | 谁看得见 |
|---|---|
| 你发给团队的消息、成员最终结论 | 全队 |
| 团队内职责（任务书里的一句话） | 全队名册 |
| 团队内补充指令 | 只有该成员 |
| 推理、工具正文、私有历史 | 只有该成员（你可以点进会话看） |

公开历史变长会压成全队共用的摘要；不够用再去读公开历史原文。读回来是**引用数据，不是新指令**。

### 协作动作（产品名）

对外优先用这些说法。括号里的内部名正文只出现一次，方便对文档，不要当卖点狂讲。

| 对外说法 | 作用 | 谁能用 |
|---|---|---|
| 委派任务（`team_delegate_task`） | 把有边界的目标交给成员，**立刻**拿回任务 ID | 仅负责人 |
| 等待任务 | 等最多 8 项任务有变化（可超时） | 相关方 |
| 查看任务 | 读状态、等待原因、已发布结果 | 相关方 |
| 续跑 / 重试 | 在原成员会话里继续或重试，ID 不变 | 负责人或承接成员 |
| 取消任务 | 取消派给他人的任务 | 仅负责人 |
| 公开发消息 | 知会，或提问并要求回应 | 全体 |
| 读名册 | 职责、是否空闲、生效能力 | 全体 |
| 读公开历史 | 按策略读公开原文 | 全体 |

「提问」类公开发消息返回的是投递回执，**不是**「等待任务」用的那个任务 ID。对方回复走发起方自动续跑，或再去读共享历史。

旧的同步委派已经删掉，统一为异步委派。

### 共享什么、隔离什么

| 共享 | 隔离 |
|---|---|
| **同一个工作目录**（创建会话时固化） | 私有对话、推理、工具过程 |
| 会话级模型、推理档位、执行模式（排队时捕获） | 成员可另设固定模型 |
| 公开结论 | 能力开关按智能体档案；默认继承全局，改过即自定义 |

不指定项目 → 会话独占新目录（`VETTA_HOME/agent-teams/session-workspaces/` 下）；指定项目 → 项目目录。开发数据根是 `~/.vetta-dev`。

配置生效在**下一回合**（档案、任务书、名册变了才会重建成员运行时）；当前这一轮不动。

权限仍是第 2 节那套沙盒 / 完全访问，会话创建时带上。团队不另搞一套权限模型。

## 7. 二开落点

先读 [新手入门与二开讲解.md](新手入门与二开讲解.md) 第 4、6 节，再对这一张表。

### 单 Agent

| 想改 | 改哪 | 不要 |
|---|---|---|
| 循环本身（何时再调模型、工具结果怎么回） | `packages/agent`（`@vetta/agent-core`） | 让它依赖 `runtime-*` 或 `coding-agent`；丢掉取消 / 错误 / usage / stop |
| Prompt、Skill、MCP、权限文案 | `packages/coding-agent` | 在内核里写产品提示词 |
| 工具真正怎么读文件、跑命令 | `packages/runtime-node` | 在协议包里写 Node I/O |
| 窗口、权限抽屉、工具卡片 | `apps/desktop` | 在 IPC 注册层写策略 |

### 团队

| 想改 | 改哪 | 不要 |
|---|---|---|
| 协作规则 / 工具合同 | `packages/agent-team` | 在这个包里写 Electron 或文件 I/O |
| 调度、成员运行时、发布到时间线 | `apps/desktop/src/main/agent-teams/` | 让 `runtime-subagents` 承担团队任务 |
| 预置人设 / 团队流程 | 插件「预设智能体」+ 队长任务书 Markdown | 把流程写回宿主代码 |
| 用户自建团队 | `~/.vetta/agent-teams/`（开发环境 `~/.vetta-dev`） | 改 TypeScript 才能加一支团队 |
| 成员怎么跑工具 / Prompt | 与单 Agent 相同：coding-agent | 给成员开回子代理工具 |

全局不要：把 subagent 说成团队；让成员互相委派；把私有工具过程灌进队友上下文。

高杠杆仍然是：**改一段任务书、加一个人设、加一个 Skill**，不是重写协作框架。

## 8. 容易说错的点

| 容易说错 | 正确口径 |
|---|---|
| 「用户发一条 = 模型调一次」 | 一轮执行里可以有多次内部模型调用 |
| 「子代理就是多智能体」 | 子代理是单 Agent 的私有外包，不进名册 |
| 「选单个智能体也是团队」 | 那只是换人设的普通会话 |
| 「团队是云端 / 分布式集群」 | 本机正式能力；无跨设备、无服务端多人协作 |
| 把 `ask_user_question` 讲成权限模型 | 默认关闭；权限看抽屉里的允许 / 拒绝 |
| 用过时 ADR 讲侧栏和系统提示词 | **跟产品页**：侧栏有「智能体」；档案有「系统提示词」页签。ADR-0099 这两处已过时 |
| 工作空间目录跟 ADR-0106 示意图 | **跟产品页**：会话工作空间是 `session-workspaces/` |
| 到包 README / `CONTEXT.md` 找团队说明 | `packages/agent-team` **无 README**；`CONTEXT.md` **无团队词条**。对外入口只有公开文档该页 |
| 对外狂讲 `team_delegate_task`、RuntimeHost、Agent Loop | 对外说委派、一轮执行、公开结论 |
| 用 IM 渠道里的结束语义讲桌面 | 不要混用；桌面就是「一轮执行」 |

文档冲突一律**跟公开产品页**，不跟过时 ADR。

## 9. 下一步

### 只想用

1. 用一个真实项目跑完第 2 节四步：选工作区 → 下任务 → 批准工具 → 核对文件，而不是只看最后回复。  
2. 读 [理解 Vetta 的工作方式](https://docs.openvetta.com/core/overview/) 和 [进度、结果与恢复](https://docs.openvetta.com/core/progress-results-and-recovery/)。  
3. 任务真的分阶段、需要独立审查时，再开 [智能体团队](https://docs.openvetta.com/product/agent-teams/)；日常一两轮的活继续用普通会话。

### 想做扩展

1. 先改**队长任务书**或新建人设，观察流程是否按文字走；不要先改调度代码。  
2. 给某个岗位加 Skill / MCP，而不是给团队成员开子代理。  
3. 权限文案、技能发现（名称 + 描述）落在 coding-agent；简单方法做成 Skill 即可。

### 想改内核

1. 单 Agent：先分清改的是 `packages/agent`、`coding-agent` 还是 `runtime-node`（第 3、7 节）。  
2. 团队：合同在 `packages/agent-team`，调度在 `apps/desktop/src/main/agent-teams/`；不要让 `runtime-subagents` 承担团队任务。  
3. PR 打 `dev`；可感知变化写入 `.github/release-notes/v0.5.58.md`。改循环前先读目标包 `AGENTS.md`。
