# ADR-0157：`edit` 用内容定位，`read`/`grep` 不再输出逐行哈希

## 状态

已采纳。取代 ADR 时代的一次本地演进：`edit` 曾以 `line:hash` 锚点为主路径，本记录把它替换为内容定位。

## 背景

`edit` 的锚点模式要求模型把 read/grep 输出里每行的 `42:h7x2→` 前缀整段逐字复制回来。这套设计在实践中产生四类失败，且每一类都不是模型能力问题：

1. **malformed**：模型没有可复制的哈希时会自己合成一个，或把 `行号:内容` 当成锚点。
2. **哈希不唯一**：指纹由行内容算出，与空白无关，因此所有空行共享一个哈希，`</div>`、`/>`、`);` 在真实 JSX 文件里重复几十次。实测某个 559 行文件里 40% 的行锚点不唯一，报错却写成 "content changed"，把模型赶去重读一个根本没变过的文件。
3. **过期**：锚点是一次性凭证，每次写入都让它下面的锚点失效。模型每次编辑后必须重新取证，表现为 `read` 次数 ≈ 1.9 × `edit` 次数。
4. **前缀泄漏**：模型把 `42:h7x2→` 当正文写进文件，需要专门的清洗逻辑兜底。

会话统计：一次真实会话 88 次 `edit` 失败 12 次（13.6%）；另一会话 53 次失败 17 次（32%），其中 8 次是 malformed、5 次是 stale，合计 76%。三个主要 harness（Claude Code 的 `old_string`、OpenAI Codex 的 `apply_patch`、oh-my-pi 默认 hashline 的 `[path#TAG]` + 行号）都不使用逐行内容哈希：行号天然唯一，文件级指纹只需在跨轮刷新一个 token，或者干脆不设。

## 决策

1. `read` 输出 `42:content`，`grep` 输出 `path:42: content`（上下文行为 `path-42- content`）。逐行哈希与 `→` 分隔符全部移除，`anchorLineHash`、`parseAnchor`、`validateAnchor`、`stripAnchorPrefixes`、`ANCHOR_SEARCH_RADIUS` 随 `shared/anchors.ts` 一起删除。
2. `edit` 的主路径改为**块编辑**：`edits: [{ oldText, oldEndText?, newText }]`。
   - `oldText` 是被替换块的首行（或它内部唯一的片段），从文件复制而来；匹配时忽略行首缩进与行内连续空白。
   - `oldEndText` 可选，标记块的末行，从 `oldText` 之后开始搜索。给出它即可只抄首尾两行替换掉中间的任意长度，这是替代"整段重抄"的关键。
   - 替换以整行为单位：块从 `oldText` 所在行的行首到 `oldEndText` 所在行的行尾被整体替换。行级粒度使缩进不参与匹配，也让 `newText` 的结构可预测。
   - `oldText` 命中多处时**拒绝**并列出候选行，要求模型增加上下文；命中零处时拒绝并说明必须复制当前文本。两者都不做"就近猜测"。
3. 单次字符级改动保留 `oldText`/`newText` 顶层模式（原有 exact-text 实现，含模糊匹配）。它是唯一能在行内就地替换的模式。
4. 批量编辑保持原子：任一块定位失败则不写入任何内容，错误里指名失败的 `edits[i]`。
5. 新增**整文件结构回归检测**（`structural.ts`）：在写入前比较编辑前后的括号/方括号/圆括号/JSX 标签开合，只有当某个维度的未闭合数或多余闭合数**比编辑前更差**时才拒绝。判据是相对的——一个本来就缺 `}` 的文件仍然可以编辑，只是不能让它更缺。只对源码扩展名生效，散文不受影响。
6. 行号前缀清洗改为按"被替换块的行号集合"判定：只有当行的 `N:` 恰好属于本次替换的块时才剥离，因此 `12:` 这类真实内容（YAML 键、时间戳）不会被误删。

## 备选方案

- **保留锚点、继续加兜底**：已积累五层补偿（宽容解析、前缀清洗、漂移搜索、歧义列举、结构守卫），每一层都在救真实的 bug，但成功率停在 86%–88%，读放大不受影响。加第六层只会让 `anchor-edit.ts` 更难验证，未采用。
- **照搬 oh-my-pi 的 hashline DSL**（`PUT 3.=3:`、`CUT`、寄存器、块操作）：表达力最强，但单个模式约 8800 行 Rust 加一套新语法；对一个还在被格式错误折磨的工具，先加语法是加重病情。值得注意的是该实现本身会给 kimi/deepseek/qwen 等模型自动降级到 `replace` 模式——即其作者也不认为最精巧的格式适合所有模型。
- **照搬 Codex 的 `apply_patch` 自由格式**：它连行号都不需要，但 `seek_sequence` 取首个匹配、不检查唯一性，文件里有相同代码块时会静默改错位置；也不做"改完等于没改"的检查。未采用其宽松部分。
- **引入真正的解析器做语法回归**：`typescript` 只是 devDependency，运行时不具备；`tree-sitter` 需要新依赖。按 AGENTS.md 的依赖约束不在本次单方面引入，先用词法级开合检测。这是本决策最明确的局限，见下。

## 后果

- 定位不再依赖一次性凭证：只要文件里的文本还在，任何时候读到的内容都能直接用于编辑，跨轮不再需要"取新锚点"这一往返。
- 逐行哈希消失后，`read` 每行少 8 个字符；`grep` 少 5 个（含两个分隔符）。
- 模型必须引用文件中的真实文本，不能引用行号。行的 `N:` 仍会随每次编辑变化，因此回执给出的是改动点附近的**当前**行号，只作定位参考。
- 结构回归检测是词法级：它认得注释、字符串、正则与 JSX 标签名，但不理解语法树，因此既可能漏判（跨语言结构问题），也可能在极端写法上误判。相比之下，误判只会在"编辑前后恰好跨过某个词法边界"时发生，且散文与无对应扩展名的文件直接跳过。
- 该变更属于公共合同变更：`edit` 的 `edits` 条目字段、`read`/`grep` 的输出格式、`AnchorEditInput` 类型名都已改变。没有保留兼容期——旧锚点需要 read 输出提供哈希，而哈希已移除，两者无法共存；保留一个永远不会被供应的输入形态只会误导调用方。历史会话记录不受影响（它们是记录，不是合同）。
