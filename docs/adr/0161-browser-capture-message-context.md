# ADR-0161：内置浏览器截图以消息上下文绑定图片和注释

日期：2026-11-27

状态：已接受

## 背景

用户需要将内置浏览器中选定的元素或区域连同注释加入对话。图片附件本身不能表达选区、页面来源和逐图注释；把这些信息拼进编辑器正文又会破坏逐图编辑及历史恢复。Runtime 已有可随消息提交、面向模型显示并写入历史的 `SessionContextRecord`，因此无需给通用 Runtime 增加浏览器专用字段。

## 决策

- Desktop 拥有版本化的 `BrowserCapture` 合同，每条记录包含一张完整可视区域截图、一个可视范围内的矩形、一条可选注释，以及有界的页面和元素信息。确认时固定图片，后续页面变化不改变已捕获内容。
- Main 仅允许当前宿主拥有的 webview guest 参与截图及检查；元素检查在隔离 world 中执行，不读取输入值或整页 DOM。元素文字和定位信息作为不可信参考数据传给模型。
- Renderer 在截图中绘制选框，沿用图片缓存落盘；对话草稿在内存中保存记录，切换对话时随草稿恢复，不新增重启恢复机制。图片沿用现有缓存清理规则，不承诺历史图片永久可用。
- 每条消息提交一个 `browser_capture_context` 上下文记录，metadata 使用版本 1，包含 messageId 和有序 captures；历史投影仅将匹配 messageId 的记录绑定到用户消息。旧历史没有该记录时保持原行为。
- 支持图片的模型收到直接图片输入及对应上下文；不支持图片的模型收到图片路径和上下文。两条路径继续遵守现有图片策略。直接输入在清空草稿前读取文件，截图 base64 合计超过 12 MiB 或读取失败时保留草稿供用户调整。

## 备选与后果

未采用通用 Runtime 的浏览器附件类型：该能力只属于 Desktop 的内置浏览器，现有上下文合同已能保留关联信息。未将注释烧进图片：独立文本便于修改、复制，且不会遮挡页面。未仅裁选区：保留周边布局能帮助模型理解修改位置。

截图记录的版本及 messageId 关联方式成为 Desktop 历史兼容边界。缓存文件消失后，历史仍保留注释与截图卡片，但显示图片不可用；实现没有新增永久资源存储。
