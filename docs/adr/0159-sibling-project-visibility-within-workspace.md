# 工作空间内的会话能看见同空间的兄弟项目

## 背景

一个产品往往散在好几个项目里：代码仓库、设计资源、官方文档。ADR-0155 把工作空间定为只存在于 Renderer 的侧栏分组，Agent 对它一无所知。结果是会话感知不到同空间的其他项目，`read` 越过会话 cwd 时还会逐次弹授权。用户只能切到别的项目会话，或者把内容一段段贴进来。

用户投票的结论是要这个能力，同时要有开关。

## 决策

1. **「看见」的含义是「告知 + 免确认只读」。** Agent 在提示词里获知同空间的兄弟项目（名称 + 路径）。`read` 工具读这些项目时不再弹授权。写入照旧逐次确认，敏感路径的 deny 列表照旧生效。它**不是隔离边界**：开关关闭时，shell、`grep` 等读 cwd 之外的路径本来就不拦，本决定不改变这一点，界面文案也不承诺隔离。
2. **开关按工作空间设置，默认开启。** 开关写在 `Space.siblingProjects` 里，在新建/编辑工作空间弹窗中切换。缺省值等于开启，旧配置无需迁移。**主空间不支持**：它是没分类内容的堆放处，里面的项目不代表在做同一件事。
3. **适用于空间内的所有会话，规则一致。** 独立对话、项目会话、Agent Team 的协调和成员会话都适用。会话所属空间按 ADR-0155 的归属规则推导：
   - 运行 cwd 落在某个项目内的，属于该项目的空间；固定到项目的 Team 也走这条；
   - 独立对话按会话路径归属；
   - 独立 Team 按 Team 会话 ID 归属，成员会话经 `ConversationOwnershipCatalog` 找到所属 Team 会话。

   项目会话看到的是**项目**，不包括同空间独立对话的内容和产物。会话自己所在的项目不算兄弟项目。
4. **只算本机的项目。** SSH 远程项目完全不参与：不出现在任何清单里，远程项目自己的会话也不注入清单。归档项目不列入，也不放行读取。开关说明里写明远程项目不在范围内。
5. **Main 直接读取空间存储。** 空间归属由主进程持有在 `~/.vetta/spaces.v1.json`（ADR-0160），Main 再用自己的项目注册表补齐名称、归档和远程信息。这样手机远程、自动化、Team 成员这些不经桌面窗口的轮次，在冷启动后也能按当前归属计算。（初版曾让 Renderer 推送一份只读镜像，ADR-0160 落地后删除。）
6. **读放行在工具执行时实时计算。** Node 沙箱新增会话级「额外可读根目录」解析器，`read` 越界时先问宿主：目标是否落在本会话当前可见的兄弟项目里。根目录取 realpath 后比较。解析失败按不放行处理，回到原有授权弹窗。项目一移出空间、开关一关，下一次 `read` 立即失效，不用等下一轮。
7. **提示词按变化追加，不改系统提示词。** 每轮 prompt 进入 RuntimeHost 前，Main 计算兄弟项目清单，与本会话**当前分支上最近一次告知过的清单**比较。告知记录从会话文档里读回，所以重启、编辑旧消息切分支都能正确处理。如果这条记录之后发生过上下文压缩，就视为未告知。清单有变化时，随本轮附一条模型可见、不在界面显示的上下文记录 `space_sibling_projects`。系统提示词前缀保持不变，缓存不抖。
   - 清单只写名称和路径，不做任何内容探测，对开发者和非开发者一样适用。
   - 按侧栏里的项目顺序，最多列 20 个，超出的写「另有 N 个」；读放行覆盖全部。
   - 清单变为空时追加一句「以下项目已不再可见」，避免 Agent 沿用旧认知。
8. 第一版不做 `@` 提到项目，也不做回复里的项目引用胶囊。

## 备选方案

- **Renderer 每轮把可见项目放进 `PromptRequest`，Main 缓存最近一次**：手机和自动化只能沿用缓存，归属刚变、桌面还没发新一轮时会滞后；冷启动后缓存为空。
- **每轮重写系统提示词里的清单**：始终准确，但清单一变，前缀缓存就整段失效。
- **开关关闭时把兄弟项目加入 denyRead，真正隔离**：比没有这项功能时更严，还要在三个平台的 OS 沙箱里都生效，与投票想要的方向相反。

## 后果

- ADR-0155 中「空间概念不进入 Agent 协议」的边界有所松动：Agent 能看到兄弟项目的名称和路径。空间概念仍不进入移动端、IM 和自动化协议。
- `read` 在同空间项目内不再弹授权。shell 写入、`write`、`edit` 的授权行为不变。
- 归属变化经 IPC 保存到主进程是异步的。最坏情况是放行或收回晚一次 `read`：要么多弹一次授权，要么多读一次刚移走的项目。
