# ADR-0152：读取时并入项目根目录的 `.mcp.json`

## 状态

已采纳。补充 ADR-0040 的三源模型与 ADR-0133 的工作区归属，不改变二者的决策。

## 背景

Claude Code 等工具把项目级 MCP 写在仓库根的 `.mcp.json`。同一个仓库在这些工具和 Vetta 之间切换时，用户要把同一份配置再抄进 `.vetta/mcp.json`，两份还会漂移。

## 决策

1. 项目层读取 `<项目>/.mcp.json`，与 `.vetta/mcp.json` 在读取时去重合并；文件本身永不被改写，安装类操作也不会写它。
2. 同名 server 以 `.vetta/mcp.json` 整体替换，不做字段合并，避免拼出两个文件都没写过的 `command` 与 `args`。
3. 与 `.vetta/mcp.json` 一视同仁：同属项目层、工作区归属（ADR-0133），不新增审批。
4. 外部文件不受 Vetta 控制：整个文件无法解析，或单个 server 无法识别（含 Vetta 暂不支持的 `type: "sse"`）时，跳过并记诊断，不影响其余配置。
5. 变量展开新增 `${VAR:-default}`（变量缺失或为空时取默认值），其余行为不变。

## 备选方案

- 逐 server 审批或全局开关：用户明确选择与 `.vetta/mcp.json` 一视同仁，未采用。
- 启动时把 `.mcp.json` 导入 `.vetta/mcp.json`：两份文件会漂移，且会改写用户仓库，未采用。

## 后果

- 打开含 `.mcp.json` 的仓库会直接启动其中的 stdio 命令，信任边界与 `.vetta/mcp.json` 相同，文档已提示。
- 项目文件没有审批这一缺口依旧存在，两个文件共同承担。
