# ADR-0153：MCP 安装与管理可指定全局或项目层

## 状态

已采纳。补充 ADR-0040、ADR-0133 与 ADR-0152，不改变它们的决策。

## 背景

`mcp.manage` 只能写全局 `~/.vetta/agent/mcp.json`。Agent 替用户安装 MCP 时没有「只装到当前项目」的选择，项目级 `.vetta/mcp.json` 只能手写；同时引导 Skill 也无从询问装到哪一层。两层的影响面不同：全局只影响本机用户，项目层随仓库提交、同事打开项目也会启动它。

## 决策

1. MCP 能力（list / get / upsert / set-enabled / remove）新增可选 `scope`（`global` | `project`）与项目根 `cwd`。两者都省略时行为不变，仍只操作全局，所以是同一版本上的增量改动。
2. `scope: "project"` 必须带 `cwd`，缺失即拒绝，不静默退回全局。`cwd` 必须是本机已存在的绝对路径目录；远程（ssh）项目没有可写的本机文件，直接拒绝。
3. `set-enabled` / `remove` / `get` 只给 `cwd` 时按名字定位：只在一层出现就用那一层；全局与项目同名则报错并要求指明 `scope`，避免误改。
4. 项目根 `.mcp.json`（ADR-0152）只读：列表与详情标 `readOnly`，写操作报错并提示直接编辑该文件。
5. 市场能力台账（ADR-0049）和托管运行时清理只对应全局安装，项目层写入不触碰它们。
6. 审批弹窗必须显示配置位置，并在用户编辑后的请求里原样带回 `scope` 与项目根；项目请求不用全局同名配置回填表单。
7. 引导 Skill `install-ability` 要求：用户没说清且当前有项目时先问装到哪一层；项目层不写明文密钥，必须用 `${VAR}` 引用。

## 备选方案

- 只在 Skill 里约定写文件路径、不改 `mcp.manage`：绕过宿主审批与校验，Skill 明令禁止手写注册表，未采用。
- 只给 `cwd`、由服务端猜层：写操作的歧义没有安全默认值，未采用；读操作与按名字定位才用 `cwd` 自动定位。
- 同时让市场 skill 支持项目层：宿主的 `install-from-market` 目前没有 scope，范围更大，另行评估。

## 后果

- 公共合同变更：`capability-sdk` 与 `plugin-sdk` 的 `official.mcp` 新增可选参数，旧调用不受影响，`pluginApiVersion` 不变。
- 项目层配置没有审批的现状不变（ADR-0152）：写入前有宿主审批，读取时没有。
- 能力市场里的 skill 仍只能装到全局。
