# 知识库是什么，知识检索如何进模型

> **本稿性质：** 给当前仓库使用者看的讲解稿，不是正式对外贡献指南。  
> **事实来源：** 基于仓库一手材料整理。  
> **官方入口仍是：** [使用知识库](https://docs.openvetta.com/product/knowledge-base/)、[上下文、工具与权限](https://docs.openvetta.com/core/context-tools-and-permissions/)。  
> **上一篇：** [智能体如何工作与多智能体协作.md](智能体如何工作与多智能体协作.md)（一轮执行、工具、团队）。  
> **整理时点：** 桌面应用版本 **0.5.58**。

文中三种标记：

| 标记 | 意思 |
|---|---|
| **【对外可讲】** | 可以对用户、客户、合作方说的产品事实 |
| **【二开要改】** | 动手改代码时该落到哪一层 |

## 0. 这篇怎么用

先钉死三件事，再往下读：

1. **知识库 = 跨项目的长期资料柜。** 不是当前项目文件夹，也不是 Skill，也不是 MCP。
2. **不是向量 RAG。** 没有 embedding、没有切块（chunk）、没有「自动塞 Top-K 片段进提示词」。
3. **发消息不会自动把知识库塞进上下文。** 要在本轮打开输入栏「知识检索」，模型再决定调不调工具。

| 你现在要做什么 | 读哪几节 |
|---|---|
| **只想对外讲**（这是什么、用户怎么用、别讲成向量库） | 第 1、2、4 节 |
| **想搞懂怎么进模型** | 第 3、4 节 |
| **想改代码** | 第 6 节；动手前扫第 5、7 节 |
| **还没搞清「一轮执行」** | 先读 [智能体如何工作与多智能体协作.md](智能体如何工作与多智能体协作.md) |

建议顺序：**先能说清「长期资料柜 + 本轮开关」，再讲标签工具；不要一上来讲向量检索。**

## 1. 一句话

**【对外可讲】**

**知识库保存需要长期复用的资料。** 导入后，后台用你选的**处理模型**整理成 wiki。对话里只有打开输入栏「**知识检索**」之后，Agent 才能用工具去查；查到的是路径和摘要，正文再读。

和上一篇的关系：上一篇讲的是「想 → 可能调工具 → 再想」。知识库只多了一步——**先打开本轮开关，工具才会出现在这一轮里**。开关关着时，整理好的 wiki 仍在磁盘上，但这一轮等于没有这块资料。

**【不要讲成卖点】** 不要说「本地向量数据库」「自动 RAG」「挂上库就会进每一轮上下文」。

## 2. 用户怎么用

**【对外可讲】** 用户不需要知道内部包名。记住：先整理，再开开关问。

### 四步

```text
侧栏「知识库」（可能带 BETA）
    → 设置里打开总开关，并选处理模型
    → 拖入文件或文件夹，等待整理
    → 回会话打开输入栏「知识检索」，再提问；核对答案能否追溯
```

1. **开启。** 若页面提示尚未开启：点「开启知识库」，或去 **设置 → 知识库设置**。打开总开关，选择**处理模型**（可带推理档位），用「测试连接」确认模型可用。**未选处理模型时，自动整理不跑。**
2. **导入。** 用默认库，或「创建知识库 / 查看全部」管理多个库。拖入文件或文件夹，或走添加资料入口。列表里看待加工状态和整理结果。
3. **提问。** 回到会话，打开输入栏「知识检索」（文案大意：开启后本轮才能调用知识库工具，并优先用知识库回答），明确依赖这些资料提问。
4. **验收。** 核对答案是否能追溯到导入的资料，不要只信一段自信的总结。

优先导入结构清晰、能抽出文本的资料。扫描版 PDF 可能要 OCR；超大目录建议按主题拆开再导。

### 和别的能力差在哪

| | 知识库 | 当前项目 / 工作区 | Skill | MCP |
|---|---|---|---|---|
| 是什么 | 导入后由后台整理、供会话检索的**长期资料** | 这一次任务的目录边界、源码、产物 | 可重复的工作方法 / 提示流程 | 连外部工具或数据的协议 |
| 用户动作 | 拖文件 → 等整理 → 本轮开「知识检索」再问 | `@` 引用，或让 Agent 直接读 / 改项目文件 | `/` 选技能或场景 | 在「能力」里加连接器 |
| 公开说法 | 跨项目长期资料 | 项目目录、引用文件 | 可复用方法和工作模式 | 接入外部工具和数据 |
| 改不改项目文件 | 导入的是资料；整理出 wiki，不是源码工作台 | Agent 可在沙盒里改项目文件 | 不代替项目目录 | 不代替项目目录 |

一句话：**项目文件是这次活；知识库是你长期攒的、跨项目还能问的资料。**

### 入口

| 入口 | 干什么 |
|---|---|
| 侧栏 **知识库**（可能带 **BETA**） | 管文件与目录结构、导入、看加工状态 |
| **设置 → 知识库设置** | 总开关、处理模型、多久整理一次、并发批次数、测试连接、马上整理、重试失败、整理记录、清空 wiki |
| 会话输入栏 **「知识检索」** | **本轮**才把检索工具交给模型 |
| 活动面板 | 可看 **知识库加工历史** |

完整设置（含知识库后台）从侧栏 **设置** 进。

### 资料在哪（本机，不依赖云）

| | 路径 |
|---|---|
| 根 | `VETTA_HOME/knowledges/` |
| 正式安装 | 默认 `~/.vetta/knowledges/` |
| 源码 `bun run dev` | `~/.vetta-dev/knowledges/`（开发数据与正式版隔离） |
| 原始资料（界面真相源） | `…/knowledges/raws/<库名>/` |
| 加工会话 | `…/knowledges/processing_records` |

**清空 wiki** = 删整理结果和整理记录，**保留原始资料（raws）**；之后会再全量整理。备份时：原始文件才是要保住的；整理结果可以再生成，不等同于原文。

### 多个库

产品页支持 **创建知识库 / 查看全部**。磁盘上 `raws/` 下每个顶层目录是一个库；有不可删、不可改名的默认「个人知识库」。

**【不要讲成卖点】** 公开文档没有写「必须在设置里勾选某个库才进这一轮」。讲解跟产品页，不要编多选挂载界面。

### 成熟度（必须降调）

| 事实 | 对外怎么说 |
|---|---|
| 公开文档覆盖状态是 complete | 正式产品文档，不是 developer-preview |
| 侧栏仍可能带 **BETA** | 界面或仍标 Beta；设置页也说标 BETA 的入口字段可能随版本变 |
| lite / 开源版**包含**知识库 | 不依赖账号、订阅、云市场 |
| 整理走你配置的处理模型 | **会耗 Token**；不是免费本地索引魔法 |
| 桌面在 macOS / Windows / Linux 支持 | 桌面能力；不要讲成移动端主功能 |

排错：先确认总开关、处理模型、测试连接、待加工文件、整理记录（公开故障排查页「知识库不整理或不检索」）。

## 3. 检索如何实现

**【二开要改】** 对外讲解可压缩成一句：**不是向量库，是「原文 → 一页 wiki + 标签目录」，Agent 用工具按标签筛页，再读正文。**

谁驱动循环仍是上一篇的「想 → 工具 → 再想」。知识库只多了：**开关 → 工具出现 → 模型决定搜不搜**。

### 分层：谁切、谁查、谁交给 Agent

产品页只写「整理后按会话状态检索」。实现按合同拆开：

> Knowledge 同样按定义与实现分离：`features/knowledge` 拥有 Tool 名称、Schema、模型描述、激活元数据和结果投影；`runtime-knowledge` 拥有知识文件、索引、查询和写入规则；最终宿主通过 `knowledgeRuntime` 注入具体实现。未注入时该能力不可用。

| 层 | 负责 | 不负责 |
|---|---|---|
| Desktop UI | 本轮开关、导入 / 加工设置 | 不自己搜，不把 wiki 拼进 Prompt |
| coding-agent `features/knowledge` | 工具名 / Schema / 何时暴露、隐形指令、加工指南 | 不选默认 `~/.vetta/knowledges` |
| `packages/runtime-knowledge` | 扫描 raws、diff、frontmatter、标签查询、写页 | 不调模型、不拥有 Tool Schema、不读总开关 |
| runtime-node | 把查询结果补成**绝对路径** | 不是向量库 |
| 加工会话（`kb-processing` 场景） | 后台 Agent 把原文转成 wiki | 不是用户对话那一轮 |

### 入库：一份原文 → 一页 wiki（1:1）

**不是切块，不是向量。** 实现里没有 embedding / 向量库。旧规划也写明不引入向量库——那是历史 Out of Scope，不是「以后偷偷做了」。

```text
VETTA_HOME/knowledges/
  raws/<库名>/…          原始文件（界面真相源）
  wiki/**/*.md           加工产物，按主题组织的树
  indexes/INDEX.md       自动生成的目录地图
  tags.json / manifest.json   可从 frontmatter 重建的缓存
  processing_records/    后台加工会话
```

每一页 wiki 带封闭的 frontmatter（id / 来源 / 标签 / 标题 / 摘要 / 时间等）。正文可以互相用 `[[页 id]]` 引用。

扫描 raws 时收下所有普通文件（跳过点文件），**不按扩展名白名单过滤**。加工指南大意：

| 资料类型 | 怎么进 wiki |
|---|---|
| 纯文本 / Markdown | 直接读 |
| PDF / 图片 | 走抽文本 / OCR；完整结果落盘，工具只回预览 |
| 陌生扩展（压缩包、二进制） | 尽量解压或转换；实在抽不出就建一页只记元信息 |

铁律：**忠实转写**，不把正文精简成摘要；`summary` 只给导航用。加工用「知识库设置」里的处理模型，耗 Token。

索引 = **标签词表 + 目录地图 + wiki 树**，不是 embedding 模型。

### 谁在搜：用户没有「搜知识库」框

| 入口 | 事实 |
|---|---|
| 用户专用「搜知识库」搜索框 | **公开文档和实现都没有。** 侧栏会话搜索是搜对话，不是搜 wiki |
| 用户动作 | 输入栏打开 **「知识检索」** |
| 然后 | Agent **自己决定**调不调工具 |

### Agent 用的三个内部工具

内部名各写一次，对外说右边这列：

| 内部名 | 对外怎么说 | 返回 |
|---|---|---|
| `kb_list_available_tags` | 列出知识库里有哪些标签 | `标签 (页数)`，**无分数** |
| `kb_filter_by_tags` | 按标签筛页（全部 / 任一 / 排除） | 命中页的 id、**绝对路径**、title、summary；**无相似度分数** |
| `kb_write_page` | 加工会话写 wiki 的**唯一入口** | **对话检索不用它** |

筛页是扫 wiki 的 frontmatter，做集合运算（交 / 并 / 补），排除孤儿页。空查询 = 全部存活页。

标签只是捷径。模型还可以读 `indexes/`、逛 `wiki/` 树、全文搜索、顺着 `[[页 id]]` 走。**正文必须再 `read` 绝对路径**，筛页结果里不带全文。

## 4. 如何和模型交互（核心）

**【对外可讲】** 这一节是对外最容易讲错的地方。记住图，不要讲成自动 RAG。

```text
默认关：
  本轮剥掉知识工具，不注入指令，模型看不见知识库

打开输入栏「知识检索」：
  隐形指令（用户聊天里看不见）+ 暴露两个标签工具
    → 模型可能调用工具
    → 工具结果回到下一轮
    → 模型再 read 正文
    → 再下一轮才用正文作答
```

**没有**「用户一发消息就自动检索、把片段预注入系统提示」这条路径。

### 开关关着（默认）

- 本轮**剥离**知识读取工具（上面那两个列标签 / 筛页的）
- **不**注入「优先查知识库」指令
- 系统提示里 **没有** wiki 正文
- 模型看不见知识库，也无法调用这些工具

### 开关开着（本轮）

发送时带上「本轮开启知识检索」。然后两件事同时发生：

1. **隐形指令**进模型上下文（用户聊天里看不见）：大意是「用户已开启知识检索，本轮请优先查本地知识库」。建议先列标签 → 筛页 → 或读目录 → `read` 命中页 → 交叉印证；都查空才退回常规回答。
2. **暴露**那两个标签工具。模型仍可能不调。

调了之后：

```text
用户开「知识检索」并发消息
  → 本轮工具表出现「列标签 / 按标签筛页」+ 隐形指令
  → 模型若调用工具
  → 工具结果（标签列表，或「id + 绝对路径 + 标题 + 摘要」）
  → 下一轮模型再读 / 搜索正文
  → 再下一轮才用正文作答
```

### 和 Skill 是不是一类

| | Skill | 知识检索 |
|---|---|---|
| 未使用时模型看见 | 名称 + 描述（发现期） | **什么都没有**（工具被剥掉） |
| 用的时候 | `/` 技能或按需读全文 | 开开关 → 指令 + 工具 → 再 `read` 页 |
| 同类点 | 都是按需，不把全文常驻提示词 | 知识库更严：连工具都要开关 |

**挂了知识库、本轮没开检索：模型等于没这块资料。** wiki 仍在磁盘上，只是本轮不进对话。

**开了开关，模型仍可能不搜。** 开关只是把工具和指令交出去，搜不搜由模型决定。

加工场景例外：后台整理那一轮没有这个开关，加工 Agent 必须能用标签工具和写页工具。

## 5. 权限与范围

| 问题 | 事实 |
|---|---|
| 检索是否走沙盒命令 | **否。** 列标签 / 筛页走注入的知识运行时，根目录由宿主传入 |
| 知识库在不在项目工作目录 | **通常不在。** 根是 `VETTA_HOME/knowledges/`，会话工作区是另一处 |
| wiki 能否被普通写文件工具改 | **否。** 路径策略拒绝写入 `wiki/`，只许加工写页工具 |
| 多个界面库 vs Agent 检索 | 界面：`raws/<库名>/` 多个库。查询扫的是**整个** `wiki/`。**没有**「只搜某一个库」的工具参数 |
| 沙盒下 `read` 绝对 wiki 路径是否总被放行 | **公开文档没写死。** 产品设计要模型去 `read` 工具返回的绝对路径；是否受「沙盒受限」拦截，不要对外断言 |

**【不要做】** 对外不要编「勾选某个库挂载到本轮」。产品页只写「按会话状态使用」；代码是输入栏**本轮「知识检索」硬隔离**。讲解跟开关 + 工具。

## 6. 二开落点

先读 [智能体如何工作与多智能体协作.md](智能体如何工作与多智能体协作.md) 第 3、7 节（谁编 Prompt、谁执行工具），再对这一张表。

| 想改 | 改哪 | 不要 |
|---|---|---|
| 切分 / 索引 / 标签算法、磁盘布局 | `packages/runtime-knowledge` | 在这里写 Tool Schema 或 Electron |
| 查询如何落到文件（补绝对路径） | `packages/runtime-node` 的 knowledge-runtime | 让协议包去选 `~/.vetta/knowledges` |
| 工具名、何时给模型、隐形指令、加工文案 | coding-agent `features/knowledge`、激活策略、提示请求运行时 | 在 Desktop UI 里拼检索 Prompt |
| 「知识检索」开关、导入页、设置 | `apps/desktop` 输入栏 / 知识库域 | 做成「发消息就自动 RAG」 |
| 加向量检索 | **当前没有。** 属于新能力，不能假装已有 | 把 `tags.json` 说成 embedding 索引 |

全局不要：把知识库讲成向量数据库；说「挂上库就会自动进每一轮上下文」；把写页工具讲成用户检索工具。

高杠杆仍然是：**改加工指南、改标签约定、改隐形指令文案**，不是先上向量库。

## 7. 容易说错的点

| 容易说错 | 正确口径 |
|---|---|
| 「本地向量数据库 / RAG，发消息自动注入」 | 不是。无 embedding、无切块、无 Top-K 预注入系统提示 |
| 「挂上库，每一轮都带着资料」 | 本轮没开「知识检索」= 模型等于没这块资料 |
| 「用户可以在框里搜知识库」 | 没有这种搜索框；是 Agent 调工具 |
| 旧规划「对 Agent 是单一全局库，多库不在本期」 | **过时。** 产品页已支持多个库；检索仍扫整个 wiki 根 |
| 到 `CONTEXT.md` 找「知识库」定义 | **没有这个词条。** 对外跟产品页 |
| 「覆盖表 complete = 界面不再标 Beta」 | 正式文档能力，侧栏仍可能带 BETA |
| 「清空 wiki 把资料删了」 | 只删整理结果和记录，**保留原始资料** |
| 把写页工具讲成检索 | 那是加工会话写 wiki 的入口，对话检索不用 |
| 开了开关就一定会搜 | 模型仍可能不调工具 |
| 用过时 ADR 把知识检索和图像生成的隔离混为一谈 | 知识检索是**硬隔离**（关则剥工具）；不要混 |

文档冲突一律**跟公开产品页 + 当前代码**，不跟旧 PRD。

## 8. 下一步

### 只想用

1. 设置里打开知识库总开关，选好处理模型，点「测试连接」。没选模型就不要指望自动整理。  
2. 往默认库或新建库拖一批**能抽出文本**的资料，等整理完成；超大目录按主题拆开。  
3. 回会话打开输入栏「知识检索」再提问，并核对答案能否追溯到导入的文件。日常问项目代码，继续 `@` 文件，不必开知识库。

### 想改整理或检索行为

1. 先改加工指南 / 标签约定（coding-agent 知识功能 + `runtime-knowledge`），观察 wiki 页和筛页结果，不要先上向量库。  
2. 隐形指令和「何时暴露工具」在 coding-agent；不要在 Desktop 里拼检索 Prompt。  
3. 多个库的界面在 Desktop；检索仍扫整个 wiki——若要「只搜某一个库」，这是新能力，当前工具没有这个参数。

### 想改内核
