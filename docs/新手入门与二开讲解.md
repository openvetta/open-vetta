## 1. 一句话是什么

**【对外可讲】**

**Open Vetta 是面向真实工作的开源桌面 AI Agent：本地优先、可扩展、由用户掌控。**

它把模型、项目文件、本机工具和可复用能力放进同一个桌面工作区，用于编码、文档、数据、研究、创意和可重复工作流。

**它不是聊天框。** 它能：

- 理解你选中的工作区（项目 / 目录）
- 在**可见的权限边界**内调用工具
- 交付**真实文件**，而不只是一段文字答案
- 保留可供检查的执行过程（计划、工具调用、进度、恢复路径）

**给谁用：**

- 要在本机完成真实任务的人
- 做技能、MCP、插件、主题的扩展开发者
- 给本仓库提代码的贡献者

**【不要讲成卖点】** 不要把「Agent Loop」「jsonl 会话格式」「`@vetta/ai`」讲成产品卖点。用户听到的应该是：工作区、权限、产物、过程可检查。

## 2. 本仓库边界（对外必讲，避免讲错）

对外讲解时，**先划清「开源客户端」和「商业服务端」**，否则听众会以为登录、订阅、官网都在这个 GitHub 仓库里。

### 在本仓 vs 不在本仓

| 【对外可讲】本仓（开源客户端） | 【不要讲成本仓】不在这里 |
|---|---|
| 桌面应用、CLI、文档站、插件 SDK、主题、Agent 内核、移动端、IM 网关 | 私有仓 `vetta-serv`：业务 API、管理控制台、**官网** |
| 本地会话、BYOK 模型、插件、主题、IM 旁路、知识库 | 账号登录 / OAuth、Vetta Go 模型渠道、订阅 / 积分 / 配额、云市场、远程模型目录下发 |
| 客户端侧的架构决策记录 | 计费、配额、订阅、权益相关 ADR（本仓 `docs/adr/` 里对应编号是空洞，这是刻意的） |

一句话：**商业服务端不在本仓库。** 本仓是客户端侧开源栈。

### lite 源码 vs 官方安装包

**【对外可讲】**

- 从 GitHub 检出源码，默认是 **lite / 开源构建**：不要求账号、订阅、远程管理或托管市场。
- 官网下载的官方安装包**可能**启用可选的 Vetta Serv（账号、订阅、托管市场）。这是**构建期选择**，不会在 lite 里静默打开。
- 二开如果只要客户端能力，走 lite / 开源构建即可，不要去改计费。

## 3. 对外讲解：用户能做什么

**【对外可讲】** 下面按用户能做什么说。不要报内部包名。

### 能力地图

| 对外说法 | 用户能做什么 | 【不要讲成卖点】不要说成 |
|---|---|---|
| 本地工作区 + 会话 | 选项目 / 目录；任务历史、文件、产物、执行详情在一起 | Agent Loop、会话 jsonl 格式 |
| BYOK 模型 | 接 Provider、OpenAI 兼容端点、本地推理；凭据留在本机 | `@vetta/ai` 协议细节 |
| 真实工具与权限 | 跑命令、改文件；敏感操作需显式批准 | runtime-tools / 沙箱分层 |
| 过程可检查 | 计划、工具调用、进度、恢复路径可见 | 内部计时条目等术语 |
| 技能 / 场景 | 把可重复方法教给 Agent；切换预设工作方式 | `SKILL.md` 目录结构 |
| MCP | 用标准协议接外部工具和数据 | runtime-mcp Port |
| 插件 | 扩展桌面 UI、文件、消息、工具 | 「渲染进程非沙箱」是风险说明，不是卖点 |
| 主题 | 换视觉系统和主题页 | theme-sdk |
| 知识库 | 在本机沉淀长期资料 | runtime-knowledge |
| 批量任务 / 自动化 | 多目录跑同一提示；定时执行（**应用需保持运行**） | scheduler 实现 |
| Claw / IM | 在已配置的 IM 渠道继续对话，代码仍在本机执行 | 网关进程池、内部 RPC |
| 智能体团队 | 有负责人、常驻分工的多 Agent；与一次性子代理不同 | 内部委派协议 |
| 设计画布 | 系统插件生成可运行的 React 界面，**不是改用户仓库代码** | `.vetd` 内部格式 |
| 浏览器操作 | 系统插件驱动真实 Chrome 读页 / 填表；登录由用户自己完成 | agent-browser CLI |
| SDK / RPC / CLI | 在其他进程里嵌入或驱动 Agent | 公开入口即可，不要深挖 `src/` |

### 扩展轻重（对外一句话）

**Skill < MCP < Plugin < Theme / SDK。**

简单、可重复的工作方法做成 Skill 就够；要接外部系统用 MCP；要改桌面界面或深度集成再做插件。不要一上来就写插件。

### 必须降调，不要当已完成卖点

| 能力 | 正确口径 | 【不要讲成卖点】 |
|---|---|---|
| 移动端 / 远程桌面 | **仅 Android**，公开覆盖状态是 **developer-preview**；Windows Desktop ↔ Android | 不要讲「Vetta iOS App」。仓库里的 iOS 相关能力是桌面插件「在模拟器里做 Apple 应用」，不是官方 iOS 客户端 |
| IM / Claw | 对外跟公开产品文档：飞书 / 微信为稳定入口，其余渠道以文档分级为准，并加一句 **「以当前客户端列表为准」** | 包内 `apps/im-gateway/README.md` 仍写 Pre-alpha，**偏旧**，不要拿它对外讲成熟度 |
| IM 会话与桌面会话 | **物理分家**：IM 会话不落在桌面「对话」同一目录 | 不要说「侧栏里同一个会话带 IM 徽章」——那是过时 README 的画法 |
| 订阅 / 云市场 | **仅官方商业安装包** | 源码 lite 没有账号、订阅、托管市场 |
| `apps/remote-relay` | 远程预览的信令配套（Cloudflare Worker） | **不要说成第五个主应用** |

### 60 秒口播提纲

1. Open Vetta 是开源的桌面 AI Agent，本地优先，工作发生在你自己的机器上。  
2. 它不是聊天框：能看项目文件、经你批准后调工具，并交出真实文件。  
3. 模型你自己接（BYOK），密钥留在本机。  
4. 技能、MCP、插件、主题可以逐步扩展，简单流程不必做成插件。  
5. GitHub 上这个仓库是**开源客户端**；登录、订阅、官网在另一套商业服务里。  
6. 源码默认 lite，不绑账号；官网安装包才可能带云能力。  
7. 桌面是主产品；命令行、文档站、Android 预览、IM 旁路也在同一套客户端栈里。  
8. 许可是 Apache-2.0，文档在 docs.openvetta.com。

## 4. 仓库长什么样

### 划分规则

**【二开要改】** 顶层按「**会不会被别的包依赖**」分，不是按语言分：

| 目录 | 规则 | 里面有什么 |
|---|---|---|
| `apps/` | 可交付应用，依赖图的**叶子**，不被任何包 import | desktop、cli-host、docs-site、mobile、im-gateway |
| `packages/` | 可复用模块，只能被 `apps/` 或其他 `packages/` 依赖 | Agent 内核、runtime、插件 SDK、主题、技能预设等 |
| `docs/` | 内部工程 / ADR / 手册 | **不会**自动同步到公开文档站 |
| `scripts/quality/` | 架构守卫与质量门禁 | 包边界检查等 |

磁盘上还有 `apps/remote-relay`，是远程预览配套，**不进入「五个可交付应用」主清单**。

### 依赖方向（只能向下）

```text
apps/*  →  coding-agent / runtime-* / capability-*  →  agent / ai
```

更贴近桌面装配时可以记：

```text
desktop → runtime-desktop → coding-agent + runtime-node
                              └→ runtime-core + 各 runtime 协议
```

**不变量：** `packages/*` 不得反向依赖 `apps/*`。跨包只走对方 `package.json` 里声明的公开入口，禁止从 `@vetta/foo/src/**` 深挖。

### 五个可交付应用

| 应用 | 是什么 | 技术栈 | 面向谁 |
|---|---|---|---|
| `apps/desktop` | **主产品**：Electron 桌面宿主 + React 界面 | Electron、Vite、React；包 `@vetta/desktop` **v0.5.58** | macOS / Windows / Linux 终端用户 |
| `apps/cli-host` | Coding Agent 的 CLI / 进程宿主，**不是 Agent 本身**；命令 `vetta` / `vetta-agent` / `vetta-agent-rpc` | TypeScript / Bun | 命令行用户；也被桌面、IM 网关拉起 |
| `apps/docs-site` | 公开产品 + 开发者文档站（docs.openvetta.com） | Next.js + Fumadocs；正文在 `apps/docs-site/content/docs/` | 用户与开发者 |
| `apps/mobile` | Kotlin Multiplatform **仅 Android** | KMP + Compose | Android 用户 / 远程桌面预览；**developer-preview** |
| `apps/im-gateway` | IM 旁路网关：IM → 本机 Agent。嵌在桌面应用里，从「设置 → Claw」启用，不单独安装 | Go | 要用飞书 / 微信等继续对话的用户；完全退出桌面会停 |

**【对外可讲】** 各端共用同一套 **Coding Agent**（产品策略：Profile / Prompt / Skill / MCP / IM 等）。  
**【不要讲成卖点】** Coding Agent 在 `packages/coding-agent`，**不是** `apps/` 里的第六个应用。不要把 `@vetta/runtime-*`、`@vetta/ai` 当卖点讲。

另：`apps/remote-relay` 只为 Android ↔ Windows 远程预览做信令中继，讲解时一句带过即可。

### 「改哪里」对照表

不要把每个包的说明书抄一遍。动手前先对这一张表：

| 你想改的事 | 落到 |
|---|---|
| 换模型协议 / Provider 适配 | `packages/ai` |
| 改 Tool Loop、流式事件、取消 / usage / stop 语义 | `packages/agent`（npm 名 `@vetta/agent-core`） |
| 改产品策略（Skill / MCP / Prompt / Mode） | `packages/coding-agent` |
| 改 Node 侧工具实现（读文件、跑命令等） | `packages/runtime-node` |
| 改桌面窗口、页面、交互 | `apps/desktop` |
| 改 Desktop 与 runtime 的装配 | `packages/runtime-desktop` |
| 加插件（SDK / 系统预设 / 外置） | `packages/plugins` |
| 加随客户端发布的内置 Skill | `packages/skill-presets` |

协议包（`runtime-core` / `runtime-tools` / `runtime-mcp` / `runtime-storage`）不写 Node I/O；Node 实现在 `runtime-node`；窗口和页面留在 `apps/desktop`。

### Desktop 四层

```text
src/main/        Electron 主进程：原生、生命周期、业务服务
  ipc/           薄注册层：只挂 ipcMain.handle，禁止写业务
  …              真正的策略、状态、持久化放在 main 的领域目录
src/preload/     安全桥；对外合同定义在这里
src/renderer/    React UI，按 domains/ 分（chat、project、settings…）
```

**【二开要改 / 不要做】** IPC 目录只允许：注册、最小校验、调用 main 业务服务、返回。禁止在 ipc 里写策略、状态机、持久化、窗口编排。业务服务也不得反向 import `main/ipc/*`。

改任何 renderer 的 `.tsx` / `.css` 前先读 `apps/desktop/DESIGN.md`。

### 再记几条不变量

- `packages/*` 不得依赖 `apps/*`
- 跨包只走 `package.json#exports`
- ADR 记录的是**当时的取舍**，不是当前实现合同；当前行为以源码、类型、测试、机械检查为准
- 计费 / 配额 / 订阅类 ADR 编号空洞（如 0016、0017、0019 等）是刻意的，那些决策在 `vetta-serv`
- 不得靠删除守卫、放宽基线、加 ignore 来掩盖包边界违规

## 5. 十分钟跑起来

**【二开要改】** 工作区用 **Bun 1.3+** 管理，**不要改用 npm / pnpm**（除非维护者明确要求）。另外仍需要 **Node 20+**（测试跑在 Node 上）。

```bash
git clone https://github.com/openvetta/open-vetta.git
cd open-vetta
git switch dev          # 或 git checkout dev
bun install
cd apps/desktop
bun run dev
```

开发应用的数据在 `~/.vetta-dev`，**不会**改正式安装版的 `~/.vetta`。

| 命令 | 实际做什么 | 【不要做】不要误解成 |
|---|---|---|
| 根目录 `bun run dev` | 只监视核心库 | **不会**启动 Electron |
| `cd apps/desktop && bun run dev` | 启动桌面开发应用 | 数据根是 `~/.vetta-dev` |
| `bun run --cwd apps/desktop dev:home` | 开发构建读写真实 `~/.vetta` | 只在确实要碰正式数据时用 |
| `bun run --cwd apps/docs-site dev` | 文档站 http://127.0.0.1:4321 | 不是产品客户端 |

### 先读哪几份（按优先级）

1. [`QUICKSTART.zh-CN.md`](../QUICKSTART.zh-CN.md) — 能跑起来  
2. [`CONTRIBUTING.zh-CN.md`](../CONTRIBUTING.zh-CN.md) — 贡献地图、PR 打 `dev`、「不接受的 PR」  
3. [`README.zh-CN.md`](../README.zh-CN.md) — 产品一句话、lite vs 商业包、扩展轻重  
4. **你要改的那个包**最近一级 `AGENTS.md` — 内部工程合同，动手前必读  
5. [`docs/dev/quality-gates.md`](dev/quality-gates.md) — 何时跑 check / test  

**【不要做】** 不要拿根目录 `CONTEXT.md` 或整份根 `AGENTS.md` 当对外入门读物。`AGENTS.md` 是给仓库内 Agent / 内部开发用的规则；对外贡献入口是 CONTRIBUTING。

## 6. 二开：我该改哪、不要做什么

高杠杆入口（仓库贡献指南原意）：**一个插件、一个 Skill、一个主题、一篇文档页**，而不是框架重写。

全局「不要做」见本节末尾；下面五条路径每条都是「改哪 / 先读 / 不要」。

### 路径 1：改 Desktop UI

| | |
|---|---|
| **改哪** | `apps/desktop/src/renderer/domains/*`；共享组件在 `renderer/shared/` |
| **先读** | `apps/desktop/AGENTS.md`、`apps/desktop/DESIGN.md`（任何 `.tsx` / `.css`） |
| 涉及 IPC 再读 | `apps/desktop/src/main/ipc/AGENTS.md` |
| **不要** | 在 ipc 写策略或持久化；业务服务反向 import ipc；硬编码用户可见文案或快捷键（文案走 i18n，快捷键进现有 keybinding）；把 `verify:ui:*` 当默认门禁 |

### 路径 2：改 Agent Loop / 模型协议

| 你要动的语义 | 改哪 | 先读 |
|---|---|---|
| 模型协议、Provider | `packages/ai` | `packages/ai/AGENTS.md` |
| Tool Loop、流式事件、取消 / usage / stop | `packages/agent`（`@vetta/agent-core`） | `packages/agent/AGENTS.md` |
| 产品策略（Prompt / Skill / MCP / Mode） | `packages/coding-agent` | `packages/coding-agent/AGENTS.md` |

**不要：** 让 `agent-core` 依赖 `runtime-*` 或 `coding-agent`；改协议时丢掉 tool / error / cancel / usage / stop 语义；用真实 Provider、付费 API 做默认测试（需明确授权）。

### 路径 3：加插件 / Skill / MCP

| 类型 | 改哪 | 先读 | 不要 |
|---|---|---|---|
| Skill | `packages/skill-presets/` 或市场源；一个带 `SKILL.md` 的目录 | CONTRIBUTING 表格；产品策略在 coding-agent | 把简单流程做成插件 |
| MCP | 用户侧在桌面设置 / 能力页配置；协议在 `runtime-mcp`，Node 实现在 `runtime-node` | 公开文档 MCP 页、开发者总览 | 在协议包里写 stdio / 凭证 I/O |
| Plugin | 系统预设：`packages/plugins/presets/`；外置：仓外用 plugin-cli，或 `externals/` | `packages/plugins/AGENTS.md`；手册真源 `docs/plugin/` | deep-import desktop 内部；改对外合同却不同步手册 / `PLUGIN_API_VERSION`；把 Preset 写进 `~/.vetta/plugins` |

Preset（随 App 发布）权限自动授予、不可卸载；外置 zip 由用户安装授权。Preset **不进** `~/.vetta/plugins`。

### 路径 4：加 workspace 包

先读 [`docs/monorepo-new-package.md`](monorepo-new-package.md)。

- 可交付应用进 `apps/*`，可复用库进 `packages/*`
- 必须同时改：包目录、根 `workspaces`、根 / desktop 的 tsconfig path maps（指向 **src 不是 dist**）
- 不要只加一个目录就以为类型检查过了

### 路径 5：改 CLI

| | |
|---|---|
| **改哪** | `apps/cli-host`：命令分发、进程生命周期、`vetta` / `vetta-agent` / `vetta-agent-rpc` |
| **先读** | `apps/cli-host/AGENTS.md`、`apps/cli-host/README.md` |
| TUI | 在 `packages/coding-agent` 的 interactive 模式里，**不要在 cli-host 里找** |
| Loop | 在 `packages/agent`，同样不在 cli-host |
| **不要** | 反向依赖 `@vetta/desktop`；改包名却不改 bin 名 |

### 全局不要做

- `packages/*` import `apps/*`；跨包 deep import `src/**`
- 裸跑 `bun test`；不要 `bunx vitest` 或直接 `vitest`（走仓库脚本）
- 手改生成文件（改生成器或事实源）
- 新增 `any`
- 静默扩大插件权限；默认打开新遥测
- 未讨论就换包管理器 / 渲染框架 / Agent Loop
- 删守卫、放宽基线来掩盖边界违规
- 未获用户明确授权就跑 `verify:ui:*` 或打真实 Provider
- 根目录 `bun run check` **不覆盖 Go**（`im-gateway` 用包内 README / Makefile）

## 7. 质量门禁（二开要过的门槛）

日常反馈循环：

```text
开发中：  bun run check:quick -- <改动文件…>
测行为：  bun run test:impact -- <改动文件…>
任务结束：bun run check          ← 不含测试
```

| 命令 | 用途 | 注意 |
|---|---|---|
| `bun run check:quick` | 变更文件 Biome + 架构守卫 | **不做**类型检查 |
| `bun run check` | lint + 类型 + 守卫 | **不跑测试** |
| `bun run test:impact -- <file…>` | 日常首选：直接测试 + 相关测试 | 范围说不清就改用 `test:changed` |
| `bun run test:changed` | 公共合同、删文件、多包、提 PR | CI 用这个 |
| `bun run test:pkg <name>` | 单包，例如 `test:pkg ai` | `--list` 看名字 |
| `bun run verify:ui:*` | Desktop 实机 UI 验证 | **仅用户明确授权**；改 UI 本身不构成授权 |

### 何时必须写测试

出现这些情况，测试是任务的一部分，不是可选项：

- 修 Bug / 回归
- 用户可观察行为、业务规则、分支、错误处理
- 新功能的**代表性用户操作流程**（不能只测纯函数或 Mock）
- 公共 API、IPC、Schema、持久化格式
- 权限、路径、凭证
- 竞态、取消、生命周期
- 跨模块边界的重构
- 重要 UI 交互

「改动很小」「时间有限」「我点过了」「类型检查过了」**都不是**省略理由。

纯文档、纯视觉且不影响交互、已被现有测试准确覆盖的机械重构，可以不新增测试——但重构那条必须**真的跑过**那些现有测试。

### 发布说明

- 路径：`.github/release-notes/v<版本号>.md`
- 版本以 **`apps/desktop/package.json` 的 `version` 为准**，当前是 **0.5.58**，对应 `.github/release-notes/v0.5.58.md`
- 该文件就是 GitHub Release 正文；缺失会导致发版质量检查失败
- 新功能、修缺陷、可感知行为变化、合并 PR、关 issue：**必须写入**；纯内部改动也要在「其他」留一句
- `apps/desktop/CHANGELOG.md` **自 0.5.58 起冻结**，不再追加

### Git / PR

- PR 打 **`dev`**，不要打 `main`
- 不要 `git add .` / `git add -A`；不要 `git reset --hard`、`git checkout .`、`git clean -fd`、`git stash`、`git commit --no-verify`、force push
- 只有明确要求时才提交；暂存时逐个列路径
- Commit message：**中文多行**（语义化标题 + 空行 + 1–3 句为什么）
- 工作区可能已有别人的改动：**不要**覆盖、回退、删除不是本次产生的变更

## 8. 讲解时容易说错的点（脚注）

对外或带新人时，优先信**公开产品文档 + 当前客户端实际列表 + 源码**。下面这些材料容易把人带偏：

| 容易说错 | 正确口径 |
|---|---|
| 「本仓库包含官网 / 登录 / 付费」 | 官网与商业服务端在私有仓 `vetta-serv`；本仓是开源客户端 |
| 「源码构建和官网下载包一样」 | 源码默认 **lite**；官方包才可能带 Vetta Serv |
| 「有五个主应用，加上 remote-relay 是六个」 | 主清单五个；`remote-relay` 是远程预览配套 |
| 「有 iOS 客户端」 | 移动端仅 Android，且是 developer-preview；iOS 相关是桌面里做 Apple 应用的插件 |
| 「IM 还是 Pre-alpha，只有飞书」 | 包内 README **偏旧**。对外跟公开产品文档，并说「以当前客户端列表为准」 |
| 「IM 和桌面共用同一个对话目录」 | 已物理分家；跟较新的 Claw 产品文档，不跟过时 README 示意图 |
| 「移动端 / 远程桌面已经正式发布」 | 覆盖状态是 developer-preview |
| 文档里出现 `packages/web-ui`、`apps/api`、`apps/admin` | **本仓没有这些目录**，是过时文档残留 |
| 「版本是 0.55.3」 | 那是**根目录** `package.json` 的 monorepo 版本。桌面发版号是 **0.5.58** |
| 把根 `AGENTS.md` / `CONTEXT.md` 发给外部贡献者当入门 | 外部入口是 README + CONTRIBUTING + docs.openvetta.com |
| 把 ADR 当「系统现在必须怎样工作」 | ADR 是历史决策；当前合同是代码和测试 |
