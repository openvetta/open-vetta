我想在packages\desktop-app这个客户端APP当中实现批量任务的功能。

# 任务

- 深入分析用户需求，你有充足的时间去实现这些需求，你需要制定充足且清晰的规划。
- 阅读 packages\desktop-app\src\renderer\App.tsx，分析用户提出的需求，拆解用户核心诉求，并转化为符合用户实际需求的 UI 操作逻辑。
- UI 需要符合基本操作逻辑，你需要梳理 UI 与需求的关联关系。
- 你需要实现具体的逻辑，补全 UI 标记的 TODO。

# 需求

- 用户需要添加批量任务执行功能，需要在菜单栏当中添加该选项，点击前往该路由，右侧面板展示该页面内容。
- 批量任务是一个基于选择多个文件夹实现、单个提示词、可长时间运行的，中断可恢复的执行过程。
- 每个文件夹是一个任务，所有的任务属于同一个项目，添加批量任务时，在侧边栏下半部分创建一个新的项目，并附带相应标识。
- 每个任务执行时单独对应会话，任务之间并无联系。
- 添加批量任务时需要提供设置项目名（标题），提示词，选择项目文件夹路径（可以选择多个文件夹）的表单项，并可以选择取消或者是保存。
- 进入批量项目页面默认展示所有的批量任务，每个批量任务附带编辑，执行，暂停，删除等操作项。
- 批量任务在执行时可以查看任务执行详情，只有运行当中的任务才有会话，这个是任务执行时的 LLM 对话，任务的执行由 LLM 完成，会话将会展示在侧边栏的下半部分，属于项目的子类。

# 代码规范

- 代码应易于维护、模块化且具有易读性。模块、文件等应遵守功能的单一职责原则，避免在同一个文件当中堆砌功能无关的代码。
- 项目文件结构设计需要有架构设计，目录命名具有前瞻性以及功能命名意义，避免无意义，含糊的文件或文件夹命名。
- 将通用代码进行封装，在合适的环节或时机使用设计模式来提高扩展性和可维护性。
- 在合适的时候可以使用设计模式来提高扩展性和代码可维护性，但是避免过度设计。
- 使用更加简洁的 tailwindcss 而不是 css 类名属性。

# 约束
