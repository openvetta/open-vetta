Execute a bash command in the current working directory. Returns stdout and stderr. Output is truncated to last 2000 lines or 30KB (whichever is hit first). If truncated, full output is saved to a temp file. Optionally provide a timeout in seconds.

IMPORTANT: NEVER use bash for operations that have dedicated tools. Use the right tool:
- File reading: ALWAYS use `read` (NEVER cat, head, tail, less, more)
- File editing: ALWAYS use `edit` (NEVER sed, awk, perl -i)
- File writing: ALWAYS use `write` (NEVER echo >, cat <<EOF, tee)
- File search by name: ALWAYS use `find` (NEVER bash find, fd, locate)
- File content search: ALWAYS use `grep` (NEVER bash grep, rg, ag, ack)
- Directory listing: ALWAYS use `ls` or `dir_tree` (NEVER bash ls, tree)
- Skill invocation: ALWAYS use `invoke_skill` (NEVER bash find/locate/mdfind to search for skill files)

Use bash ONLY for: running scripts, package managers (npm, pip, cargo, etc.), git commands, compilers, interpreters, complex piping, or commands with no dedicated tool equivalent.

PDF image conversion safety:
- Avoid running `pdftoppm` at a fixed high DPI on unknown PDFs. Large page boxes can render to images over 17000px on one edge and may trigger OOM.
- Prefer the dedicated `extract_text_from_pdf` tool for OCR. If `pdftoppm` is necessary, inspect page dimensions first with `pdfinfo -box` and choose DPI from `floor(max_edge_px * 72 / max_page_edge_pts)`; use a conservative max edge such as 10000px and reduce DPI further after OOM.

# Git Safety Protocol

When running git commands, follow these rules strictly:
- NEVER run destructive git commands without explicit user request:
  - `git reset --hard` — destroys uncommitted changes
  - `git push --force` / `git push -f` — can overwrite remote history
  - `git checkout .` / `git restore .` — discards all local changes
  - `git clean -fd` — deletes untracked files permanently
  - `git branch -D` — force-deletes a branch
  - `git stash drop` — permanently discards stashed changes
- NEVER skip hooks: do NOT use `--no-verify` or `--no-gpg-sign` unless user explicitly asks
- NEVER use `git add -A` or `git add .` — these can stage unrelated files. ALWAYS add specific files by path
- NEVER amend commits unless user explicitly requests it — amending can destroy the previous commit
- Before any destructive operation, consider if there is a safer alternative

# Skill / Scene Directory Protection

Skill and scene directories are READ-ONLY. NEVER write, create, modify, or delete any files inside:
- ~/.vetta/agent/skills/
- ~/.vetta/skills/
- ~/.vetta/scene/
- .vetta/skills/ (project-level)

All output files and artifacts MUST be written to the user's working directory, NOT into skill or scene directories.
